# Public dataset discovery for decision models

Checked November 6, 2026. This is a research shortlist, not a scored benchmark or a training manifest. No new training, GPU allocation, model inference or Jev API evaluation was started. Cards, repository documentation and metadata were inspected; this is not a complete row-level overlap audit. Current targets are quality, model routing, tool-call safety and financial/legal decision tasks.

## Recommended first shortlist

| Dataset | Decision to evaluate | Published scale / splits | Fit and preparation |
|---|---|---|---|
| [When2Call](https://huggingface.co/datasets/nvidia/When2Call) | Answer directly, call a tool, ask for missing information, or say it cannot answer | 3,652 MCQ test cases; separate SFT and preference training releases | Excellent four-choice match. Measures whether to use tools, not permission or execution safety. Keep official test untouched during training. CC BY 4.0. |
| [TS-Bench / ToolSafe](https://huggingface.co/datasets/MurrayTom/TS-Bench) | Is the proposed action safe given the request, history, environment and tools? | 2,194 train; 789 validation; 7,182 evaluation actions across AgentHarm-Traj (731), ASB-Traj (5,231), AgentDojo-Traj (1,220) | Strongest direct pre-execution tool-safety fit. Labels are safe / controversial or potentially unsafe / unsafe, encoded 0 / 0.5 / 1. Preserve all three classes and report the original strict/loose binary scoring separately. Apache 2.0 release with upstream notices. |
| [R-Judge](https://github.com/Lordog/R-Judge) | Does an agent interaction contain a safety risk? | 569 human-annotated multi-turn interaction records | Direct binary classification with risk descriptions. Exclude the gold description from inputs. Evaluate safety judgment; explanation judging is a separate task. Small enough to reserve as an external test. |
| [RouterBench](https://huggingface.co/datasets/withmartian/routerbench) | Which actual LLM should receive a request? | 30k+ prompts with responses, costs and performance scores for 11 LLMs | Much more relevant to real model routing than capability-category labels. Score realized selected-model quality, cost/quality curves and regret, not just agreement with one arbitrary best-model label. Historical model pool and prices. |
| [RouterArena](https://github.com/RouteWorks/RouterArena) | Does a router preserve quality across real model choices, domains and difficulty? | Dataset card: 8,400 questions; 9 domains, 44 categories; framework has full/robustness modes | Evaluation-only. Its rules prohibit fitting, calibration and training on its questions, labels, templates or configs. Use separate routing training data. Prefer cached outcome labels when available; the full framework can require downstream model calls. |
| [ToolRet](https://huggingface.co/datasets/mangopy/ToolRet-Queries) | Which tools are relevant to the request? | Multi-source query/tool retrieval collection; Decision Index publishes a versioned candidate-selection/scoring recipe | Ranking rather than a single tool-choice label. Keep original relevance judgments and evaluate nDCG/recall. Unjudged tools are not verified negatives. Query and tool corpora have source-specific terms. |
| [BFCL](https://github.com/gorilla-llm/gorilla/tree/main/berkeley-function-call-leaderboard) | Select a tool; decide when no available function applies; check a proposed call | Versioned function-calling benchmark; the existing Decision Index conversion uses selected BFCL v3 tracks | Selection/irrelevance can be classified; full argument generation and multi-turn execution are different tasks. Report the exact version and adapted subtask rather than calling a classifier result a full BFCL score. |
| [ContractNLI](https://stanfordnlp.github.io/contract-nli/) | Is a contract hypothesis entailed, contradicted or not mentioned? | 17 hypotheses over 607 NDAs; official train/dev/test; Decision Index uses 123 test documents | Strong legal-reasoning extension beyond clause topics. Preserve whole documents and group all hypotheses by contract. Long context may exceed the current release cap. CC BY 4.0. |
| [RAGTruth](https://github.com/ParticleMedia/RAGTruth) | Is a response supported by the supplied evidence? | Nearly 18k responses with manual span annotations; Decision Index has a 2,700-response test track | Useful groundedness/review gate. Use canonical upstream splits; distinguish response-level hallucination detection from span localization. Source contexts include redistribution/noncommercial restrictions. |
| [CLINC150 + OOS](https://github.com/clinc/oos-eval) | Route intent or reject an out-of-scope request | 150 intents plus OOS; Decision Index has a public track | Adds abstention/OOS coverage missing from the current banking test. Preserve the original full taxonomy for full-task claims. |
| [AgentDojo](https://github.com/ethz-spylab/agentdojo) | Detect indirect prompt injection and preserve authorized task completion | Versioned interactive suites, including banking | Strong financial-services alignment. Use labeled trajectory derivatives for static classification; the native benchmark measures end-to-end utility and attack success in an agent environment. A classifier-only adaptation is not the original agent score. |
| [TraceSafe](https://github.com/cycraft-corp/TraceSafe) | Identify unsafe or invalid multi-step tool traces | Repository describes 1,170 records across 12 risk categories plus benign controls | Direct binary/fine-grained classification; synthetic mutations of BFCL-derived traces. Canonical Hugging Face data is gated; access was not obtained during discovery. Keep each baseline trace and its mutations together. |

## What the linked Jevmaxxing collection contributes

The [resolved collection](https://huggingface.co/collections/MaziyarPanahi/jevmaxxing-6adb06405d99a631582208b0) has source-label datasets and Jev-annotated variants. Their `gold_*` and `jev_*` fields are different signals. Use source references for evaluation; use teacher probabilities only as separately declared supervision or disagreement analysis. Card counts and split-safety claims below are publisher statements unless explicitly noted.

| Release | Actual task/source | Recommended role / overlap issue |
|---|---|---|
| [Policy Verification 180K](https://huggingface.co/datasets/MaziyarPanahi/Jev-Policy-Verification-180K) | HelpSteer2/3 response scores, helpfulness, preferences and principle fulfilment; 139,431 of 180,000 rows use `score` | Useful response-quality/policy-principle supervision. | [Safety/Refusal 150K](https://huggingface.co/datasets/MaziyarPanahi/Jev-Safety-Refusal-Decisions-150K) | Derived from Aegis 2.0; 23,644 upstream source rows expanded into 150k decisions | Helpful guard classification curriculum; alternative packaging of an already listed source, not an independent external benchmark. |

All Jev variants above record a `jev-1.13.0` teacher, while our last live comparison resolved `jev-1.14.0`. Teacher agreement is not current Jev accuracy. Source-specific terms remain relevant despite the uniform typed format.

## Decision Index compatibility

The [public kit](https://github.com/apolinario/decision-index) already provides typed conversions/scorers for BFCL, ToolRet, RouterBench, CLINC150/OOS, SGD, ContractNLI, When2Call, RAGTruth, HoVer, FinEntity and phishing classification. Reuse its pinned edition, source revisions and task-specific metrics. Current README says the live board is 0.4 and the reproducible public suite remains 0.3; the official Full score uses private tests maintained separately. Running public data cannot reproduce the private Full score.

The Qwen 27B project already has a public Decision Index 0.3 result. Some suite tasks are also familiar from Gemma training, especially BANKING77. Additional public evaluation is valuable, but it is not an entirely new blind holdout for this project.

Our release accepts 2–8 candidates and 2,048 packed tokens. RouterBench has 11 model candidates; full-taxonomy intent tasks, retrieval candidates and long legal/agent contexts also need format/context work. Preserve original candidates and content for official comparisons; report adaptations and coverage separately. No adapter was implemented in this discovery pass.

## LLM Gateway routing pilot: additional discovery

The [primary protocol](https://llmgateway.io/benchmarks/smart-routing-2026-09-26-protocol.json) fixes 80 prompts: 25 easy tasks, 15 exact-answer reasoning tasks and 40 IFEval cases. There are four arms and two output caps, producing 640 calls across the same 80 prompts. I verified complete prompt/arm coverage within each snapshot and identical prompt messages across caps. This is a small general-text pilot, with no tool execution or financial-specialist workload.

The [published results](https://llmgateway.io/benchmarks/smart-routing-2026-09-26-results.json) supply responses, pass/fail checks, errors, normalized cost indices, timings and routing metadata. Fixed baselines are `gpt-6-luna`, `gpt-6-sol` and `gpt-6-astra`. Routed requests use Jev with an eligible five-model pool. Some pool members are observed only when selected, and the mid-priced fixed baseline is outside that pool. Consequently the export supports an offline three-fixed-model routing diagnostic; a fully matched evaluation over the original five candidates requires missing downstream outcomes. `selectedModel` and difficulty are router outputs, not oracle route labels. Multiple models may pass a task.

Useful [reproduction practices](https://github.com/theopenco/llmgateway/tree/733b8212c7c2a05edc563b0b6c1ee8127dc86be0/scripts/benchmarks) include retaining failed/billed calls, accounting for classifier charges, keeping cap runs separate, and reporting paired uncertainty plus strict/sensitivity scoring. The runner uses model-default reasoning/temperature, so it measures the configured service rather than isolating its classifier. Do not present these repeated prompts as 640 independent examples or as a large routing training set.

Recommended role: small regression/replay set and protocol reference. The repository's mixed license covers code outside commercial components under AGPLv3 and retains third-party terms; IFEval is Apache 2.0. A separate training-data permission/split audit has not been performed. Public JSON files were inspected and hashed; no model calls were made.

## Proposed next evaluation selection

Start with **When2Call, the three TS-Bench evaluation configurations, R-Judge, RouterBench, ContractNLI, RAGTruth and CLINC150/OOS**. Reserve **RouterArena** as a stricter independent router test and add **AgentDojo banking** for a later guarded-agent evaluation. TraceSafe is a strong additional audit once its canonical access is available. Use the source-label AgentToolDecisions release and allowed upstream training partitions as curriculum candidates after an overlap audit.

Freeze training/development/calibration/test source families across *all* packages before fitting. Exclude gold labels, Jev receipts/probabilities, evaluator success flags and future trace steps from model inputs where the task is pre-execution safety. Use the full state instead of the truncated `state_preview`. Report safe-action false blocks, unsafe-action misses, per-task macro-F1, calibration/coverage and native routing utility separately. Keep severity-0.5 handling explicit. This pass ends at dataset discovery and selection.
