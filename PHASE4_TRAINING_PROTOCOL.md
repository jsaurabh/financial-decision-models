# Aligned training, validation, calibration and core test; separate transfer

Authorized by the user's explicit request to train financial, legal, measured model-routing and tool-safety capabilities and evaluate the same capabilities on separate slices. This supersedes the earlier blanket evaluation-only reservation for native training portions. CPU optimization is deferred. No production deployment or broad-superiority claim is authorized by training completion alone.

## Capability alignment

Every core fold contains the same nine tasks: financial numerical answer verification, full77-class banking intent, MAUD legal contract review, full100-class LEDGAR clause topic, three-way tool-action safety, interaction injection detection, malicious-request detection, quality routing and cost-aware routing. Sample and adapter policies are identical across core folds. Native/source gold is used; Jev predictions are never training references.

- **Financial verification:** TAT-QA's native train/dev/test-gold contexts, arithmetic answers checked with a safe numerical-expression interpreter. Pair each valid native answer with a deterministic numeric counterfactual, preserving scale/precision. Both variants stay in one table/context family. This is verification, not the official answer-generation score. FinQA is a separate source-transfer track.
- **Banking and legal topics:** native BANKING77/LEDGAR partitions with the complete77/100-class taxonomy in every fold. Candidate membership does not depend on the gold label; only order varies. BANKING77's native training pool supplies training/validation/calibration by stable request-family hash; native test supplies core test. LEDGAR's native validation supplies validation/calibration.
- **MAUD:** published row folds share almost all contracts, so combine them and repartition whole contract IDs70/15/5/10. Use native unambiguous `<NONE>` subquestion rows, complete2..11-class native MAUD task ontologies and at least4 contract families per class before partitioning. Exclude conflicting identical-input labels and whole tasks with missing training-class support; record all exclusions before prediction. Shared duplicate clause contexts are removed from lower-priority folds without linking every distinct contract through a generic boilerplate clause.
- **Tool safety:** repartition TS-Bench's fully annotated supervised train+validation pool70/15/5/10 by whole user-request families. The same three native targets appear in every core fold. Its separate native trajectory-eval files expose only action-harm scores; do not fabricate missing injection/malicious labels or substitute another task into core testing.
- **Measured model routing:** RouterBench's released complete11-model outcomes, both0/5-shot views and quality/cost-aware objectives. Assign query families70/15/5/10, keeping all views/objectives together. Accept all native utility ties. Training uses set-aware cross-entropy. Model performance/cost profiles come only from retained training rows; candidate outcomes, benchmark task names, gold answers and future per-request costs never enter router inputs. Cost-aware utility is quality−10×USD cost.

Exact/near content groups and native source families cannot cross core folds. Native-role collisions resolve toward heldout folds; cross-fold duplicate contexts are excluded from the lower-priority fold. Audit with normalized exact matching and64-permutation MinHash candidate retrieval followed by exact three-word Jaccard>=.85. Approximate matching cannot prove semantic independence. Native report/document IDs are unavailable for some TAT-QA/LEDGAR cases; record the released-context/text-cluster grouping limit explicitly.

Freeze all file hashes, source revisions, exclusions, class coverage and model-specific input lengths in `data/phase4-manifest.json` before fitting. Both models use identical training rows. Never truncate inputs. Remove an entire training source family if any selected view exceeds either model's8,192-token training envelope; retain every requested validation/calibration/test input and report unsupported/error coverage. Source/code/manifest hashes must match for resume.

The shared output vocabulary has128 codes. Actual core training/evaluation uses at most100 candidates;128 is capacity, not a claim of validated128-way accuracy.

## Separate transfer suite and historical exposure

Source/task transfer is evaluation-only and reported independently: FinQA numerical verification, LegalBench clauses/insurance, RouterArena's historical three-model replay and TraceSafe trajectory risks. Filter entire transfer families against every core fold using exact/near and bidirectional long-text containment (at least8 words/40 characters). Never use transfer labels for fitting, checkpoint selection, calibration or choosing the backbone.

These transfer sources and some conventional core benchmark examples have been evaluated by earlier project models. Disclose that history. A fixed benchmark test excluded from this training cycle is not a claim that the project has never inspected it. New private-production/fresh-independent claims require a separately sealed and representative adjudicated holdout. Preserve earlier results as diagnostics; do not replace old failure receipts.

## Selection and final evaluation

Record initial validation before any optimizer update. Check the fixed640-case validation-only selection subset every500 updates and at the last update. Select the highest equal-four-domain validation score: coverage-penalized semantic macro-F1 for classification (MAUD first averaged over review questions), and one minus normalized native oracle regret for routing. Stop after two consecutive scheduled checks without improvement. Keep the initial model if no fine-tuned checkpoint improves it; report selected step0 honestly.

After selection, compute the full validation metrics and fit one positive scalar temperature on the separate calibration fold using set-aware NLL. All calibration inputs remain requested, and support/coverage are disclosed. Do not optimize thresholds on core/transfer tests. Preserve the selected checkpoint, temperature, optimizer/RNG/config hashes and all validation metrics privately. Publish an immutable release revision.

The primary backbone is chosen by its full-validation selection score; exact ties choose Gemma. Report both frozen candidates on identical core-test and transfer payloads, regardless of which wins. Test files are packaged separately and are not extracted on the training VM until selection/calibration/release are complete. Jev requests may be cached independently in the background, but neither test scores nor Jev test predictions enter training or model selection. Require resolved Jev1.14.0; flag provider changes rather than pooling them.

Report accuracy with missing decisions wrong, semantic macro-F1, per-class errors, benign false blocks, unsafe misses and complete coverage. For routing, report actual released quality/cost/utility/regret, all ties, and the training-profile fixed-router baseline; never replace utility with tie-inflated oracle-choice accuracy. Core and transfer scores are never pooled into one headline.

Use paired source-family bootstrap95% intervals (10,000 replicates, seed20261107) for classification accuracy differences and routing quality/utility differences. Average classification tasks equally within each domain, with MAUD review questions weighted equally. Holm-correct the five prespecified core comparisons: financial/legal/tool-safety accuracy and quality/cost-aware routing outcomes. A broad claim across these represented capabilities requires positive paired evidence in all five, no lower coverage, no lower semantic macro-F1 on any core classification task and no worse observed native tool-safety false blocks/unsafe recall. Report task losses/inconclusive results explicitly. Public pretraining exposure remains unknown; native benchmark wins do not establish production financial-service safety.

Permit at most one recovery after confirmed runtime deletion, preserving optimizer/RNG and exact job hashes.
